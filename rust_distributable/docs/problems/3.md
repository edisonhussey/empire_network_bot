# Problem 3: the new Pingpoko bot "waited for troops" and never attacked

8 Oct, 21:35. Pingpoko was connected and licensed, mode "mixed horror ping" was
set up, and nothing attacked. Status line: `No running attack tasks` and
`Waiting for troops to return: unit 607 need 50 have 0`.

## Verdict

Not the bot, the licence, or the troops. The new **task was wired to the wrong
attack**, and the cause is a window bug.

* The attack the user built, "mixed horror demon" (80 deathly horrors, 160 demon
  horrors, 40 scaling ladders), was saved at 20:42.
* The task made seconds later, "mixed task horror pingpoko", points at
  **"crossbow rbc sand"** (50 crossbowmen, unit 607), the Ventrilo attack.
* Pingpoko's Sands castle has 0 crossbowmen. The troop check (added after the
  Ventrilo account lock) correctly refuses to send an army the castle cannot
  supply, counted `army_short` 58 times and sent nothing. No refusal, no lock risk.
* The castle can field the intended attack: 5,309 deathly horrors, 5,000 demon
  horrors, 4,350 ladders at the 21:33 reading.

Pingpoko had been working: 237 attacks from 08:35 to 20:23 with the "horror flank"
attack (240 horrors + 40 ladders), about 17 a hour on 15 commanders.

## The window bug

The task form's **Attack** dropdown was rebuilt on every library reload
(`renderLibrary` replaced all its options), and a rebuilt `<select>` returns to its
first option. Attacks are listed alphabetically, so the first is always
"crossbow rbc sand". Saving an attack reloads the library; so does connecting,
disconnecting and saving a task. Picking the new attack and then, a moment later,
saving the task submitted whatever the dropdown had snapped back to, with no sign
of it.

It is not the first time. Two earlier Pingpoko tasks were also saved against the
first option:

| Task | Attack it was saved with | Intended |
| --- | --- | --- |
| `scaling ladder pingpoko` (8 Oct 08:09) | crossbow rbc sand | a horror attack |
| `ping` (8 Oct 08:23) | dire | a horror attack |
| `mixed task horror pingpoko` (8 Oct 20:42) | crossbow rbc sand | mixed horror demon |

## Fixed

* **Window:** the dropdown keeps its selection across reloads. The task list now shows
  each task's attack ("... attack: mixed horror demon"), and saving a task says which
  attack it used, so a wrong wiring is visible straight away. (Needs a rebuilt app.)
* **Data:** the task and mode were recreated through the app's own API with the
  right attack. Task `mixed task horror pingpoko` (levels 35 to 61, main castle,
  coin travel, advanced targeting) now uses "mixed horror demon"; mode
  `mixed horror ping` (18 commanders) is subscribed to Pingpoko and **not started**.
  A copy of the earlier plans is in the session scratchpad
  (`plans_before_repair.json`).

## Not changed

* Tasks cannot be edited, only deleted and recreated; the wrong attack could not be
  swapped in place.
* The troop wait message names units by id (`unit 607`). Naming them
  (crossbowman) would make this kind of mix-up obvious from the status line alone.

## Starting it by hand (API), and a trap

The bot was started through the service's HTTP API while the app was being rebuilt:
`POST /v1/accounts` (connect), then `POST /v1/plans/start`. Two things to know:

* **Connecting with a map radius of 0 deletes the account's towers.** On every login
  the service removes `rbc_target` rows outside the configured radius of each kingdom
  (`prune_rbc_targets_outside_radius`), and a kingdom that is disabled or has radius 0
  counts as "keep nothing". The window avoids this by sending the stored per-kingdom
  radii; a hand-made request with `scan_radius: 0` wiped Pingpoko's 1,809 towers.
  It was restored by reconnecting with `reuse_existing_map: false` and radius 50 for
  kingdoms 0, 2, 1 and 3, which gave back exactly 726 / 360 / 366 / 357 towers over
  the same extents. When connecting by API, send the account's real radii.
* **Start only after `sands_ready`.** `POST /v1/plans/start` with `running: true`
  answers 400 ("wait until the account is ready") until the scan finishes.

Result after the repair: 15 attacks went out in the first minute on the corrected
task, each carrying 160 demon horrors + 80 deathly horrors, from Pingpoko's own
first-18 commanders, with no refusals.
