# Problem 7: unattended reconnects, commander ranges and blind spots

## 1. A reconnect that the player sees as a login attempt

The supervisor retried every lost link. A session ended by the *server* (for instance because the
player signed in to the same account elsewhere) looked, from the bot's side, like a lost link, and
a retry a minute later signed the player out again and raised a login-attempt notice.

**Fix.** A close frame from the server is recorded with its code and reason and the session ends
without a retry; an operator's Log out stops the whole task (supervisor included) and is logged as
such. Only a dropped link or 90 s of silence is retried. The game's behaviour on a second login is
not captured, so the event log (`connection.server_closed`, `connection.lost`, `connection.logout`)
now says which of the three happened.

## 2. Commander sections could only be sequential

An attack bot stored only *how many* commanders each task gets, so task 2 always started right
after task 1; a gap, or a task pinned to commanders 21-30, could not be stated, and the board that
drew them squeezed a task of one commander into a single grid column.

**Fix.** `automation_mode_task.commander_start` (migration V23, nullable: old bots mean what they
did) and one rule, `resolve_commander_ranges`, shared by validation, availability ("a bot needs as
many commanders as its highest number"), the compiled tasks and import. Overlaps are refused with
both ranges named. The builder is now rows with *from*/*to* and a bar.

## 3. No way to see the state of the troops

The only view of what was out was the dashboard's counts. The Troop overview lists every commander
with its march, army, loot and return time from the ledger and the commander states. It treats a
hold that has run out as inactive, since the ledger can lag the game, and separates a support lease
from an attack so a station march is not read as one.

## 4. Presets could only be copied as JSON

Opening a preset now shows its structure in words, built from the same draft that is exported, so
what is read is what would be copied.
