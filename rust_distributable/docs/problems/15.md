# Problem 15: alliance chat was heard and thrown away, and the packet docs were in three places

## The problem (packets and database)

The alliance chat arrives as `acm`, pushed to every online member with no request. The session heard it and dropped it,
so there was no record of who asked an alliance mate for a buff and when. Two details were not obvious from the one
capture (`{"CM":{"PID":4616599,"PN":"Dawn Reaver","MA":0,"MT":"Can I get rage bonus please"}}`):

* There is **no timestamp**. `MA` is the message's *age in seconds*: the client's `ChatMessageVO` sets the written time to
  `now - MA`. It is 0 for a live message, but a history (`acl`, `{"CM":[...]}`) carries real ages, so the time must be
  derived, not assumed to be "now".
* `MT` is escaped (`&percnt;`, `&quot;`, `&145;`, `<br />`, `%5C`, brackets). A `%` in the text would also corrupt the
  frame if left raw; the client undoes the escapes before showing it.

The packet documentation was also scattered: `docs/network/` (some commands), `docs/network_packets/` (the support
commands, plus captures and topic notes), the proxy tool's `learned_info/`, and loose `new_info/` notes. A new command
had no obvious home and the same fact could live in two places.

## The fix

* `empire-core/src/chat.rs` (pure): parses `acm` and `acl`, decodes the escapes, derives `sent_at = arrival - MA`.
* Migration **V27** `alliance_chat`, per account, newest 2,000 kept, with a de-duplication window so a history read does
  not double a message heard live. `direct/chat.rs` stores what arrives; `GET /v1/chat` (`API_VERSION` 55) serves it; the
  **Chat** tab (`views/chat.js`) shows name, time and text per account. See [`../architecture/chat.md`](../architecture/chat.md).
* **One docs structure** under `docs/network/`, described in its [`README`](../network/README.md): one file per packet
  command named as on the wire, all in the same template (direction, evidence, code, purpose, request, reply, rules, handling,
  captures, open questions); raw packets in `captures/` named `<command>_request|response|push|<variant>.txt`; multi-packet
  flows in `sequences/`; cross-command notes in `topics/`. `docs/network_packets/` is gone and its files moved
  (`station_sequence` is `sequences/support`, `incoming_gam` is `topics/incoming_movements`, the captures were renamed);
  the Rust tests that include captures and every link were updated. New in the same shape: `kut`, `msk`, `kpi`, `gcu`,
  `sce`, `rue`, `acm`, and a captures set for them taken from the 2026-10-17 recordings.

## Not verified

* The new code has not run against the live server. `acm` is tested with the captured packet and the pasted chat; `acl`
  (the history) is read from the client code and never captured.
* Messages sent while the account was offline are not stored; nothing requests the history.
* `proxy_packet_monitor/learned_info/` still holds that tool's own older copies of some notes, and the loose `new_info/`
  notes are now redundant; neither was deleted.
