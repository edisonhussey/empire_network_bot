# Problem 20: login refused after `vck` again (game client 1.171.8 to 1.171.9)

## The problem (packets)

On 2026-10-26 between 10:12 and 10:18 both accounts lost their link (first `Connection reset without closing handshake`, then
`RSV2 or RSV3 set` while the game servers were restarting for the update). Every login after that stopped at the version check:

| Direction | Frame |
| --- | --- |
| server -> client | `nfo` / `core_nfo` (`XML_E4K` 788.RC.03, `XML_EP` 788.03), `rlu` |
| client -> server | `vck` payload **1171008** |
| server -> client | `vck` `6.1177.3 / 43.0.0`, **status `1`** |

`event_log` recorded `connection.version_rejected` and `connection.failed` (the guard from [problem 10](10.md) worked: no `lli`
was sent, and the session was not retried). The frame order, the server build (`6.1177.3`) and the API version (`43.0.0`) are the
same as the day before; only the client's patch number moved.

## Cause

The public bundle (`empire-html5.goodgamestudios.com/default/` -> `Game.bundle.e2ca3c4ee155ea53c7c7.js`) now reports
`TranspilationEmpire` **1.171.9**, so the wire value is `1171009`. The `vck` command and the handshake are otherwise unchanged.

## Fix

* `empire-core/src/session.rs`: `CLIENT_VERSION = "1171009"`.
* New `cargo run -p empire-socket --example vck -- [url] [server header] [version]`: runs the app's own handshake
  (`SessionMachine`) up to the server's `vck` reply and stops, so **no credentials are sent**. It prints `ACCEPTED` (status 0) or
  `REFUSED`. Checked live 2026-10-26: `1171009` accepted on us1 (`EmpireEx_21`) and world2 (`EmpireEx_49`); `1171008` refused.

## When it happens again

Follow the steps in [problem 10](10.md), then confirm the new value with the `vck` example before rebuilding and reinstalling the
desktop app (the installed app runs its own copy of the service).
