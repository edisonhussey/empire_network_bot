# Problem 25: the UI could only be developed through the Tauri window

## The problem

Every UI change needed the Tauri app (`npm run tauri dev`, or a full DMG build to see it in the installed app), and there
was no way to use the bots from a browser. The coming UI redesign needs a fast loop: reload the page for UI changes,
rebuild only the daemon for Rust changes. The bots must keep running when the page is closed.

No packets or database tables changed.

## What was already true

* The UI used no Tauri APIs: `desktop/src/api.js` called `fetch("http://127.0.0.1:47821/v1/...")`, nothing else.
* The daemon was already its own process that outlives the window (`--service`, or the stand-alone `empire-daemon` that
  process_monitor starts), and already allowed `http://localhost:1420` in CORS.

## The fix (0.1.78, API unchanged at 57)

* `empire-daemon/src/web_ui.rs`: the daemon serves `desktop/dist` as a fallback after all `/v1` routes, so
  `http://127.0.0.1:47821/` is the control panel. Off when the folder is absent (the app's `--service`).
* CORS also allows `http://127.0.0.1:1420`.
* `desktop/src/platform.js`: API base (own origin when the daemon served the page), `copyText`, `notify`. `api.js` and
  `main.js` use it instead of a fixed URL, `navigator.clipboard` and `alert`.
* `utils/scripts/web-dev.sh` (`oa web`): cargo-watch daemon + Vite; refuses to start a second daemon on the port.
* process_monitor's `github_gge_bot` card links to the page (outside this repo: `~/Desktop/process_monitor/apps.toml`).

See [`../architecture/web-mode.md`](../architecture/web-mode.md).

## Verified

* `cargo test -p empire-daemon web_ui`: path-escape tests pass. `npm test`: 95 pass, including `platform.test.js`.
* A debug daemon on a scratch data folder and port served `/` (`text/html`), the hashed JS asset (`text/javascript`), `/v1/health`
  as before, `404` for `/../Cargo.toml`; in a browser the page loaded and its calls went to its own origin
  (`GET /v1/licence 200`), no console errors.
* `cargo check` of `desktop/src-tauri` (the window's code is unchanged).

## Not verified

* The Tauri window was not opened after the change (its only change is `platform.js` picking the same URL as before).
* cargo-watch is not installed on this Mac, so the restart-on-save path was not run.
