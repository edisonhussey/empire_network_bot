# Problem 10: every login dropped after `vck` (the game updated its client version)

## What we saw

Both accounts (pingpoko on world2, ventrilo on us1) stopped logging in at once. The `event_log`
showed the socket opening and then, within about 15 ms, `connection.lost`:

```
connection.connected   wss://ep-live-world2-game.goodgamestudios.com/
connection.lost        WebSocket protocol error: Connection reset without closing handshake
connection.reconnect_scheduled   retry 1 in 52s
```

It never reached `login_ok`, and there was no `login_rejected`. That is what made it look like
a network fault rather than a refusal.

## What the packets (`network_message`) showed

The handshake got as far as the version check, then died:

| Time (ms) | Direction | Frame |
| ---: | --- | --- |
| ...888250 | server -> client | `nfo` / `core_nfo` (`XML_EP` 787.03) |
| ...888254 | server -> client | `rlu` |
| ...888517 | client -> server | `vck` payload **1169011** |
| ...913866 | server -> client | `vck` payload `"6.1174.6"`, **status `"1"`** |
| ...913881 | | `connection.lost`, 15 ms later |

Two things matter:

* The `vck` reply carried status `1`. The test fixture and every good session use `0`. The
  game's own client treats any non-OK `vck` status as `VERSION_TOO_LOW` / `VERSION_TOO_HIGH`
  (`CastleVCKCommand` in `Game.bundle`), and the payload is the server's build number.
* The reset came 15 ms after that reply. The round trip to the server is about 60 to 100 ms, so
  the server hung up before our `lli` could even have arrived. It was not a reaction to our
  credentials. (`lli` is deliberately not stored in `network_message`, see
  `record_safe_outbound`, so its absence from the table says nothing by itself.)

## Cause

We send the web client's version in `vck`. It was hard-coded as `1169011` (game client 1.169.11).
The public client bundle at `empire-html5.goodgamestudios.com/default/` now reports
`TranspilationEmpire` **1.170.22**. The client builds the wire value by padding each part to
three digits (`1` + `170` + `022`), so the server now expects **`1170022`**. The server refuses the
old value and drops the socket.

It "suddenly" stopped because the game updated between the 08:29 login and the 10:54
reconnect. Nothing in our own commits touched the handshake (the 09:09 commit was pacing and
PVP only).

## Why it was hard to see

* The refusal was a dead socket, not a protocol error, so the supervisor classified it as a
  lost link and retried (twice, then gave up) with no hint that the version was the cause.
* We still went on to send the `lli` credentials frame after a refused `vck`.

## Fix

All of it is small and sits where the handshake already lives:

* `empire-core/src/session.rs`: the version is now one named constant, `CLIENT_VERSION =
  "1170022"`, used as the `SessionSettings` default (it can still be overridden with
  `GGE_CLIENT_VERSION` in `empire-login`).
* `empire-core/src/session.rs`: a `vck` reply with a non-zero status ends the handshake
  (`SessionPhase::Failed`) and sends **no** `lli`, so credentials never go to a server that is
  about to hang up.
* `empire-daemon/src/direct/version.rs` (new, with `mod version;` in `direct/mod.rs` and one
  check right after `on_server_text`): a refused `vck` logs `connection.version_rejected` and
  ends the session with `ClientVersionRejected`, which is not a lost link, so it is not retried.
  The status line now reads: `the game refused client version 1169011 (server build 6.1174.6).
  The game has updated: set the new version in empire-core CLIENT_VERSION. Not retrying`.
* Tests: `a_refused_client_version_ends_the_handshake_without_sending_credentials` (core) and
  `only_a_non_zero_vck_status_is_a_refusal` (daemon).

## When it happens again

1. `event_log`: look for `connection.version_rejected` (or, on an older build, a reset within
   about 15 ms of the `vck` reply) and read the `vck` status in `network_message`.
2. Fetch `https://empire-html5.goodgamestudios.com/default/index.html`, take the
   `Game.bundle.*.js` it names and find `TranspilationEmpire` `version:"A.B.C"`.
3. The wire value is `A` + `B` padded to 3 + `C` padded to 3. Put it in `CLIENT_VERSION`, rebuild
   and reinstall the desktop app (the installed `/Applications/OpenAuto.app` runs its own copy
   of the service, so a source change alone does nothing).

Not checked: whether the server accepts a range of versions. Only the latest bundle's value is
known to work.
