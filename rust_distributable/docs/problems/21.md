# Problem 21: an expired licence could not be replaced, and the sidebar showed another account's time

## The problem (licences and database)

On 2026-11-07 at 06:44:54 UTC the `ventrilo-stage0` and `pingpoko-stage0` licences expired. Every login then got through
`vck` (`1171009`, status 0) and stopped at the licence check: `event_log` shows `licence.needed` with "the licence for this
game account is unusable: licence has expired". It looked like the handshake again, but was not.

Three faults made it worse than an expiry:

* **No way to move an account to a new licence.** `licence_activation` has a unique index on `(server, player_id)` and a
  binding was written once (`INSERT OR IGNORE`). A licence with a *new* `license_id` for an already-bound account could be
  installed but never bound: the login kept resolving to the expired one. Only the same id with a higher revision worked.
* **No per-account view.** The window had one "Add a licence" dialog for the whole install, and `GET /v1/licence` reports
  one *primary* licence (an activated valid one first).
* **"4 days left" was someone else's.** The sidebar's plan line drew that primary licence, which was then a great-emperor
  one (valid to 12 Nov), while the account in view had none. `expiryLabel` also said `0h remaining` for an expired licence.

## The fix

* `empire-core/src/licence.rs`: `signed_claims` checks the signature and fields without the time, so the castle an expired
  licence was issued for can still be read. `verify_token` is that plus the time checks, unchanged in effect.
* `empire-core/src/store.rs`: `rebind_account_licence` removes the account's old binding and licence row and binds the new
  one in one transaction.
* `empire-daemon/src/licence.rs`: `for_account` (the licence bound to the player, else an unbound one issued for its
  server and main castle), `replace_for_account` (rules in [security.md](../architecture/security.md)), and
  `require_for_player`: a live session now re-checks the licence bound to *its player* rather than the id it logged in
  with, so a replaced licence takes over without a new login.
* `empire-daemon/src/account_licence.rs` (new): `GET`/`POST /v1/licence/account`, which find the account's server
  (endpoint and header), player (`account_alliance`) and main castles (`owned_castle`, kingdom 0, area type 1). API 57.
* Window: the empty Support tab is now **Licence** (`views/licence.js`, `views/licence-model.js`): the account in view's
  licence, a drop box (file or paste) that replaces it, and the sidebar plan line for that account ("Expired",
  "No licence" or the time left). The plan button opens the tab, and a login refused for a missing or unusable licence
  switches to it. Requests are made only when the tab opens, the account changes or a token is dropped.
* Tests: `a_new_licence_replaces_the_one_an_account_has`, `a_licence_for_another_account_is_refused_on_the_licence_tab`
  (daemon) and `licence-model.test.js`.

* `bind_or_validate`: when the licence bound to an account is unusable (expired) and a valid, unbound licence issued for
  its server and main castle is installed, the login moves the account to it (`unbound_match`, then
  `rebind_account_licence`). That covers the activation screen, which still only installs a token when every licence has
  expired. Test: `a_login_moves_an_account_off_an_expired_licence`.

## Not changed

The window still needs *some* valid, bound licence to open (`LicenceGate::require` gates the account list and similar
reads); per-account enforcement is at login, at every session check, and at bot start (the session's own tier).
