# Problem 29: Storm Islands was a placeholder in Create task

## The problem

Create task listed the Storm Islands kingdom, but no target type worked there: storm forts are not towers. They appear,
get taken and vanish, so the tower logic (a learned list, cooldowns counted down locally) could not find or keep them.

## The fix (schema 30, API 57 unchanged)

A new target type, **Storm Islands fort** (`Destination::StormLevelRange`, target kind `storm`), default levels 60-80:

* `empire-core/src/storm.rs`: storm fort rows (`gaa` type 25, owner -1/-403), level codes, free only with both cooldown
  fields 0, scan windows around the storm castle and the 5.5-12.5 s scan wait.
* `store/storm.rs` + `V30` `storm_target`: forts seen, vanished (dropped by a rescan of their window), reserved, attacked.
* `direct/automation.rs`: storm picks only take a fort seen in the last 2 minutes; with none, the bot reads one more map
  window (`AwaitStormScan`), only when the scan wait is over and the client's current kingdom has no work; a taken or
  vanished fort (adi row, adi timeout, any cra refusal but a short army) is forgotten, not an error; a sent attack is this
  account's cooldown on that fort.
* UI: the target type, shown only for kingdom 4, chosen automatically there, levels set to 60-80.

Packets: [`../network/gaa.md`](../network/gaa.md) (Storm Islands section). Flow: [`../architecture/storm-islands.md`](../architecture/storm-islands.md).

## Verified

* Unit tests: the captured fort row (`[25,551,542,4,-1,12,0,8,0]`) reads as a free level 60; player-owned rows and other
  types are not forts; scan windows start at the castle's own window (`546:520`, as the client did).
* Store tests: nearest fresh fort first, no fort twice, stale sightings ignored, a rescan drops vanished forts but keeps
  attacked ones.
* Bot tests: no fort → scan of `546:520` → the reply's level-60 fort is picked and its map opened; a fort taken before the
  inspection answers is skipped with no incident; an unexplained storm refusal is tolerated, a `313` still stops the bot.

## Not verified

* A live storm run. The account's storm castle must be in `owned_castle` (it is learned at login; ventrilo's appeared after
  its last login, so log in again before starting a storm task).
* The level codes 7-9 vs 12-14 (two families) come from the Python bot; only code 12 = 60 is confirmed by the capture.
* Which `cra` status the server gives for a vanished fort.
